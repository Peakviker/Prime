# Factory — агент, который собирает и деплоит веб-приложения

Отдельное eve-приложение. Берёт описание сайта, пишет его в песочнице,
собирает, проверяет результат и публикует на Vercel, возвращая URL.

Модель ходит через **OpenRouter**, а не через Vercel AI Gateway.

## Из чего собран

Всё — коробочные возможности eve, ничего не переизобретено:

| Что | Откуда |
|---|---|
| Оболочка и файлы в песочнице | встроенные `bash`, `read_file`, `write_file` |
| Процедура сборки через Vite | навык `agent/skills/build-with-vite/` — грузится по требованию |
| Публикация | инструмент `agent/tools/deploy_static_site.ts` |
| Долговечность прогонов | Vercel Workflow — движок eve по умолчанию |
| Отказоустойчивый вход | стандартная auth-цепочка eve-канала |

Единственный написанный код — инструмент деплоя. Он выполняется **в
рантайме приложения, а не в песочнице**: токен Vercel читается из
`process.env`, и ни песочница, ни модель его не видят. Модель решает, *что*
публиковать, но никогда не держит ключ, которым это делается.

## Запуск

```sh
cp .env.example .env.local     # заполнить OPENROUTER_API_KEY и VERCEL_TOKEN
pnpm install
pnpm exec eve dev              # локально, с терминальным REPL
```

Без терминального UI, чтобы дёргать по HTTP:

```sh
pnpm exec eve dev --no-ui --port 2381
curl -X POST http://127.0.0.1:2381/eve/v1/session \
  -H 'content-type: application/json' \
  -d '{"message":"Собери страницу-визитку и задеплой её."}'
```

Прод:

```sh
pnpm exec eve build && PORT=3000 pnpm exec eve start --host 0.0.0.0
```

## Что проверено, а что нет

Проверено в песочнице разработки:

- `tsc --noEmit` — чисто.
- `eve info` — 0 ошибок, 0 предупреждений; навык и инструмент подхвачены.
- `eve build` — полная сборка проходит, провайдер OpenRouter попадает в бандл.
- `eve start` — сервер поднимается, `/eve/v1/health` отвечает `200`.
- Неаутентифицированный `POST /eve/v1/session` на прод-сервере получает `401` —
  auth действительно fail-closed.
- В dev-режиме сессия создаётся, ход стартует и доходит до вызова модели.

**Не проверено:** сам вызов модели и деплой. Сеть той песочницы, где это
писалось, блокирует `openrouter.ai` и `api.vercel.com`, поэтому прогон
останавливается на `MODEL_CALL_FAILED — Forbidden`. Это ограничение среды, а не
кода: всё до сетевого вызова отработало. Первый запуск на машине с открытым
egress — обязательный шаг приёмки.

## Что нужно знать до первого запуска

**Модель слабая, и это заметно.** `nvidia/nemotron-3.5-lightning:free` — free-tier
модель, и длинные циклы с инструментами ей даются плохо: она теряет задачу
после нескольких вызовов и хуже восстанавливается после ошибки сборки. Поэтому
инструкции написаны предельно процедурно, а промпт прямо велит предпочитать
один статический `index.html` любому фреймворку. Модель меняется переменной
`OPENROUTER_MODEL` без правки кода — если результат разочарует, начните с этого.

**Размер контекста задан вручную.** eve обычно берёт его из каталога AI
Gateway, где моделей OpenRouter нет, — без явного значения агент не стартует с
403. В `agent.ts` стоит консервативные 32 768 токенов: занизить безопасно
(компакция сработает раньше), завысить — нет. Уточните реальное окно выбранной
модели и поднимите значение.

**Локально нужен Docker.** Без него eve откатывается на `just-bash` —
симулированную оболочку без настоящих бинарников, где нет ни `node`, ни `npm`.
Сервер поднимется, но собрать реальный сайт не сможет. Пакет `just-bash` стоит
в devDependencies, чтобы `eve start` не падал, но для настоящей работы нужен
докер-демон.

**Деплой спрашивает разрешение один раз за сессию** (`once()`). Публикация в
интернет — внешний side effect, и первый за сессию требует подтверждения
человека. Для более строгого режима поменяйте на `always()` в
`agent/tools/deploy_static_site.ts`.
